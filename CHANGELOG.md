# Changelog

## 5.0.0 (unreleased)

- **The promises said out loud are now a fourth compiled book, with one announcement and one question as their discipline (#193, F16).** `MemoryKernel.commitments` (`src/commitment/`, contract `docs/commitments.md`) records who promised what, when it comes due, and how it closed — the owner's promises, the agent's own (symmetric, same book), and a third party's promise reported to the owner. **Recognition is deterministic and runs on the hot path:** a clause needs a future marker, an action and a first person, or a third party's promise verb with a recipient cue; questions, requests, hypotheticals, speaker hedges, habits, the past, negation and wishes are refused, and a third party's plan without a recipient is not a promise. A conditional promise (`等发货后…`) carries its `dueCondition` instead of an invented instant; a reported or conditional promise is recorded as `tentative`, a first-person dated one as `explicit`. **The state machine is derived:** `pending` / `due_soon` / `overdue` come from `dueAt` against the read's `now`, and `completed` / `cancelled` from a closed row, so a clock alone never appends a row. `compile` re-derives from the raw turns and appends only the new `OPENED` / `CLOSED` rows, so the same call is safe at a turn boundary and at DREAMING. **Announce once:** `surfaceDue` returns the arrived promises and writes a `SURFACED` row keyed by the due instant; a second query for that occurrence is silent, including after a restart, and F6's proactive candidate reads the same mark so the shell cannot repeat it. **Ask once:** hedged completion evidence (`应该已经发了`) closes nothing and earns exactly one question ever, marked by an `ASKED` row. Explicit completion (`文件已经发了`, or an artifact that names the commitment in metadata) closes it and appends the evidence turn to `sourceRefs`; `dismiss` silences one occurrence and leaves the promise in the book, which is F7's feedback loop read as a book mark until F7 lands. `dueForAgent` is a pure read of the agent's own arrived promises, wired into F14's existing `openLoops` port, so an agent wakes up remembering what it said it would do without consuming the announce mark. **The identification gate is measured, not asserted:** `__tests__/fixtures/commitment-seed.ts` holds 30 explicit promises and 40 non-promises (Chinese and English, first and third party, dates and conditions) and the contract test refuses the round below 90% precision or recall; this round measured **precision 1.000 / recall 1.000** on that curated set, which is reported with the boundary that it is curated rather than independent. **What pays for it:** no table, no column, no migration, no dependency and no bin — five ledger event types, one additive surfacing source (`commitment`, proactive only) and four thin host-API reads; the session face is not modified, only its open-loop port is used. The contract test holds the frozen owner/status/method/field/event/error tables plus the ticket discriminators (owner-content-due item by item, non-promises excluded, once-only surfacing, completion with evidence, one ambiguous question, agent wake), each measured red under a rollback probe. User-visible effect, in one line: a promise made in conversation comes back at the right time — once — and when the evidence that it was kept is murky the companion asks one question instead of nagging.

- **A project's craft is now a third compiled book: how the work actually got done, recalled by the task description and never by a skill's name (#192, F15).** `MemoryKernel.procedures` (`src/procedure/ProcedureCompiler.ts`, contract `docs/procedure-compilation.md`) compiles this project's own attempts and the guides imported through #143 into procedure entries carrying their steps, tool choices, grade and `sourceRefs`. **Evidence is structured, never free text:** an own attempt is a `task_event` whose `metadata.procedure` names the domain, key, steps, tools, outcome and whether it is a checklist; a user correction is a `user` turn whose `metadata.procedureCorrection` names the key and whose text replaces the practice; an imported guide is the same descriptor on a row the import channel already marks `imported: true`, so a capability's code still belongs to its installer and only the written guide enters memory. **Confidence is support count:** one attempt is `tentative`, two successes are `established`, a failure is recorded in `support.failures` and keeps the entry tentative until a success follows, and a correction is `established` at once and outranks the practice it replaced. **An imported guide is recallable and compiled, and an own practice outranks it** — the two entries coexist per (domain, key), the imported one is not deleted, and the frozen score's origin weight puts `correction` over `experience` over `imported`. **Consumption is by task:** `recall({ task })` cue-matches domain, key, title, steps and tools, and `assembleTask` renders the start-of-work lane plus the owner's preferences read through F5's own recall (the preference ledger is not copied into a second book). A `checklist` entry whose domain the task hits is delivered whole under any `targetTokens` — the assembly's budget may drop ordinary entries, never a checklist and never an excerpt — implemented as the same frozen tier-to-policy table shape the surfacing face uses for sensitivity, not a second mechanism. **What pays for it:** no table, no column, no migration, no dependency and no bin — a version is a `memory_events` row on `procedure-entry:<entryId>`, a recompile leaves one receipt, and the surfacing face gains one additive source (`procedure`, only when the caller supplied a task cue) with no change to its classifier or channel policy. The contract test holds the frozen grade/origin/delivery/method/field/event/error tables plus the four ticket discriminators — second-task assembly versus first, imported-versus-own ranking, checklist-under-squeeze, and sourceRefs walkable to the real ledger rows — each measured red under a rollback probe. User-visible effect, in one line: on the next same-kind task the companion starts with the steps, tools and preferences that worked last time, and a release or safety checklist arrives whole instead of as a remembered sketch.

- **A session is a ledger projection now, not a transcript that gets summarised and dropped (#191, F14).** `MemoryKernel.sessionContext` (also `KernelAgentMemoryBackend.sessionDigest` / `.recallSession` / `.assembleSessionContext`) adds the three primitives the ticket names. **Digest:** a turn that slides out of the verbatim tail becomes an entry in a compiled document, and the entry is the ledger row's exact text with its `sourceRefs` — no model, no paraphrase; a decision, a number or a name is therefore verbatim by construction, and `digestAnchors()` names those fragments so the contract test can compare them. The DREAMING-boundary deep compiler is declared as `SessionDeepCompiler` and deliberately not wired. **Recall:** the session ledger paged newest-first by time, topic (the session's episode `topic_path`) or keyword (a case-insensitive substring, including CJK), scoped to the agent's captured session, returning the row's own text. **Assembly:** six lanes in a frozen render order (`pinned`, `profile`, `digest`, `working_set`, `recall`, `tail`) and a separate fill priority; a turn is fitted to `targetTokens`, which the caller reads from its model configuration rather than a kernel constant. Over budget, the lowest-priority lane becomes a browse-only pointer with its ids kept and the text still one `recall` away; the `pinned`/`profile` bytes are the stable prefix and are trimmed last, never stubbed. Every cut is in the returned `decisionTrace` and, when non-empty, in a `session.context.assemble` row in `trace_events`, so "why is the context this long" survives the turn. **Kill-side:** the digest locates the session, recall walks back to the exact words, and the open loops the kernel already owns — F2 pending wake intentions and F6 wake/prospective candidates — are re-read from their services into the `working_set` lane, so a restart can answer what we were doing, where we were stuck and what comes next with `sourceRefs`. **What pays for it:** no table, no column, no migration, no dependency and no bin — the digest reads `ConversationCaptureService`'s lane, recall reads the same `memory_events` rows, and the assembler is a pure function over the digest plus caller material. Nothing is removed this round; the round is additive and says so. The contract is `docs/session-context.md` with the frozen lane/priority/stability, digest-field, recall-mode, decision-trace and error tables; `__tests__/session-context.contract.test.ts` holds them plus the long-session anchor, bandwidth, stable-prefix, downgrade-trace and kill-side discriminators, each measured red under a rollback probe. **Two observatory findings land in the same round:** the star map now applies an agent's scope to the whole project before its node budget (#204), so a target node outside the project's top 20k is no longer filtered away and `truncation`/the roster report that view's own counts; and the recall detail's parent chain now reuses `TraceStore.getDecisionChain` with the page's 32-hop display bound supplied at the page, while `TraceQuery` keeps the full chain (#206) — the store gains an explicit `readOnly()` path that refuses writes and does not create the table, so the observatory's read-only connection stays zero-write, and the 40-hop discriminator shows the page truncating with a marker while the query returns all 40. User-visible effect, in one line: a long conversation's early decisions remain reachable word for word, every turn's context is a fixed-size view that names what it left out, and the observatory no longer loses an agent's nodes or half a decision chain to a display budget.

- **What the companion may recall and surface now depends on where it is speaking (#162, F8).** A connection's occasion — `private`, `group` or `public` — is declared by its channel at registration and resolved from that binding; it is never read from a call. `MemoryKernel.occasionScope.register({ channelId, occasion })` issues an opaque binding, and `new KernelAgentMemoryBackend(kernel, { binding })` binds it to the connection. A connection with no binding, or one holding an object the registry did not issue, answers as `public`, the strictest occasion — never `private`. Recall applies the rule at its single exit, after the social, secret, agent-scope and phase admissions; surfacing applies it beside F6's channel policy, so a candidate needs both. `private` and `high` material appears only in `private`; `group` withholds it and withholds another person's private or high material while still allowing their daily remark; `public` shows the owner's daily material and project-public material only, and no third-party material at all — which is what makes the three sets strictly decrease. Third-party material is the ledger's existing `other` speaker (F7), and project-public material is the existing `metadata.imported` marker (#143); neither is a second taxonomy. F6's declared `occasion?` is absorbed: the binding wins, and a disagreement is recorded in the candidate's trace as `occasion=mismatch` with the declared and resolved occasions. A filtered recall names itself — `suppressed` carries `occasion_private_tier` or `occasion_third_party` with ids, and `zeroExplanation.kind` is `occasion_filtered` when everything was withheld — so a filtered answer is not a silent zero. The contract is `docs/occasion-scope.md`, which also freezes the minimal channel shape F12 (#166) will consume; `__tests__/occasion-scope.contract.test.ts` holds the document tables and the four discriminators (strict decrease on both faces, a forged `private` declaration on a group connection, a group's third-party private turn, and an unbound connection). **What pays for it, merged:** no table, no column, no migration, no dependency and no bin — the registry is in-process, the material classification reuses `AgentScopeRules.isImportedMaterial` and the conversation capture's `other` marker, and the visibility rule is one table lookup; the only new module is `src/occasion/`, and `explain-recall` takes the same optional binding instead of a second occasion path. Nothing is removed this round: the face is additive by nature and says so rather than dressing a new module up as a merge. User-visible effect, in one line: a group or public connection no longer hears the owner's private or high material, another person's private material, or a forged claim that it is in a private conversation, and every withheld item is visible in the trace.
- **The owner's reaction to a surfaced candidate now modulates what the companion raises next (#161, F7).** `MemoryKernel.surfacingFeedback` (also `KernelAgentMemoryBackend.recordSurfacingFeedback` / `.surfacingFeedbackState` / `.resumeSurfacingType`) records `engaged`, `ignored` or `stopped` as a `memory_events` row on `surfacing-feedback:<projectId>`, carrying the F6 `candidateId`, its type (the F6 source), its `sourceRefs` and the injected instant, so the reaction is auditable and replayable. The modulation is arithmetic over those rows and calls no model: a type's level is `floor(consecutiveIgnored / 3)`, capped at 3, and at level 1 or above the type is withheld from `proactive` until `lastIgnoredAt + 6h × 2^(level − 1)`; a `stopped` type stays at zero until the owner explicitly resumes it, with no automatic restart however long it has been; an `engaged` reaction resets the count and the cooldown, so frequency can recover instead of ratcheting down forever. Only the proactive channel is modulated — an asked answer is the owner's question being served. The decision travels in F6's `decisionTrace` as a new `modulation` step (`none`, `throttled`, `stopped` or `not-applicable`) appended after `occasion`, and a modulated candidate is returned on the `withheld` face with its reason rather than disappearing silently. The state is readable per type (counts, level, `cooldownUntil`, `stoppedAt`, `stoppedTypes`) and returns the frozen rules table itself, so there is no hidden parameter. **What pays for it, merged:** no table, no column, no migration, no dependency and no bin — the ledger is the state, as F2 and F5 store theirs; the type dimension reuses F6's source list rather than inventing a second taxonomy; and the state is replayed on demand instead of cached, so two readers agree. Nothing is removed or merged this round: the face is additive by nature and says so rather than dressing it up as a merge. The contract is `docs/surfacing-feedback.md`, held by `__tests__/surfacing-feedback.contract.test.ts` (14 tests): the document's type/outcome/event/field/rule/state/API/error tables are compared with the code, and the ticket's discriminators are measured — three consecutive ignores take a type from three appearances to zero across three instants while a service without the feedback port still shows three; a stop holds a profile type at zero for thirty days until an explicit resume; throttling one type leaves the other surfacing; the state's counts reconcile with the audit rows; and the asked channel stays unmodulated. Removing the modulation gate from the candidate query fails four of those tests (measured). User-visible effect, in one line: a kind of memory the owner keeps ignoring comes up less often, one they told to stop stays quiet until they restart it, and every suppression is visible in the candidate's trace instead of being a silent drop.
- **Surfacing now has a kernel-side candidate query with deterministic sensitivity grading (#160, F6).** `MemoryKernel.surfacing.candidates()` (also `KernelAgentMemoryBackend.surfacingCandidates`) answers the proactive channel and the asked channel separately, and every candidate carries its `sourceRefs`, reason, confidence, freshness/validity and one of three tiers: `daily`, `private` or `high`. The kernel gives candidates; the shell decides whether to speak. Channel and occasion are declared by the caller and recorded, never trusted — occasion trust is F8 (#162). Sources are only landed products: F2's pending wake intentions and confirmed/deferred prospective memories, F5's current profile entries, and the ledger's raw turns; F15's playbook and F16's commitment ledgers are not invented. The classifier is deterministic and calls no model: a keychain mark is at least high and is hard-withheld from both channels because #142 already keeps that text out of every read lane; high text (medical, identity, secrets) and raw event types (tool calls and results) are graded from frozen marker tables. `private` is withheld from `proactive` by default and allowed when asked; `high` is likewise withheld from proactive and allowed when asked, except for the keychain hard withhold. Every candidate's `reason` is rebuilt from its `decisionTrace.steps` (`source`, `freshness`, `sensitivity`, `channel`, plus `occasion` when declared), and the contract test reconciles candidates and withheld entries item by item. The contract is `docs/surfacing-candidates.md`, with the frozen channel, source, tier, candidate/result/withheld/freshness/trace and error tables, the acceptance sample set (a medical record is not daily; a birthday is not high), and the narrow `SensitivityTagSource` interface F10's life-information marks will enter through without a version bump. **What pays for it:** no storage, no table, no column, no migration, no dependency and no bin — the query reads the existing stores and reuses F2's due products and F5's profile entries; the secret-mark predicate moved to `src/security/SecretMarks.ts` so recall and surfacing read one rule instead of two copies. The round adds `src/surfacing/`, one contract document and 34 contract tests. User-visible effect, in one line: the shell can ask the kernel what is worth surfacing, and the kernel answers with reasons, freshness and a sensitivity tier instead of leaking a high-sensitivity memory into a proactive moment.
- **A resident Cog upgrades itself the way a CLI install does: 停服 → 换版 → 迁移 → 启服 → 回滚, and it never does so silently (#165, the 5.0 upgrade item, Ryu 2026-11-13).** #150 landed the whole cycle for the command-line form (`cogmem update` stops the recorded resident service, swaps the package, opens the database with the new build — which is the migration — gates on `doctor`, starts it again, and reinstalls the old version when a step fails). A companion that is *already* resident has no operator at a keyboard to run that command, so the cycle moves into the shell: `/upgrade <tree>` is the operator's trigger, `shell/src/upgrade/*` is the cycle, and the five requirements Ryu fixed on 2026-11-12 are each a discriminator in `shell/test/upgrade.test.ts` rather than a paragraph of intent. **① 先预告**: the command answers with a receipt — a transcript line, not a model turn — naming `from → to` and that it is going offline for a moment, before anything is stopped. **② 只从静默态**: the first line of `CompanionShell.upgrade` refuses unless the lifecycle is `IDLE` or `DORMANT`; `RUNNING` (someone's turn), `DREAMING` (the night's integration) and `WAKING` all get a refusal that names the state, and a refusal stages nothing, snapshots nothing and promises nothing — the discriminating tests drive the real state machine to RUNNING and to DREAMING and assert that the request file, the snapshot and the promise are all absent. **③ 完成必回报**: the report obligation is an F2 wake intention (`upgrade_report:<id>`) written *before* the handoff, so it is durable in the checkpoint at the moment the resident can go offline; speaking the report consumes it, which is F2's own auto-close and not a second bookkeeping store. The promise is not fired as an idle wake (`ClockService.dueWakeIntent` skips it) because the idle path would consume the obligation without ever speaking the report it exists for. **④ 失败也必报**: every exit path of the supervisor writes `<dataDir>/upgrade/last.json` — a failed stop, a failed snapshot, a failed gate, a failed switch, a failed start, a failed health check, and a rollback all name the step, the checks and what the rollback did or could not do. The one case a file cannot cover is a supervisor that vanishes: then the request outlives it with no outcome, the next start sees no live supervisor, and the resident reports **升级后沉默** as a failure — the veto-level failure is a report, not an absence. The report itself rides the existing "你不在时发生了什么" (`PresenceReport.upgrade`), so a rolled-back upgrade is read back on attach beside the dreams and the fulfilled commitments, and reported exactly once. **⑤ 旁置 + 快照 + 健康门 + 自动回滚**: the new tree is staged *beside* the serving one under `<dataDir>/app/versions/<version>/` (dependencies symlinked, not copied; a staged tree that is stale or source-less is refused rather than installed), the brain is snapshotted **before** the new code opens it (`exportSnapshot`, one checksummed file, the kernel's own cross-device format), the staged tree's own process runs the gate — open the database (that open *is* the additive migration), the doctor's static checks, the soul, and a recall self-check that writes a probe turn and recalls it by its token — and only then does the service switch and start. Any failed check restores the snapshot, points the service back and starts the old tree; the old tree was never touched, which is what makes "旧版可服务" a one-argv change rather than a rebuild. The live half of `runDoctor` (health face, attach socket, unit) needs a process, so it runs after the start and a failure there rolls back too — the split is written down in `shell/UPGRADE.md` rather than passed off as one gate. **The handoff is a real process boundary, and it is the point:** a resident that stops itself mid-upgrade and re-execs is how a service ends up neither old nor new (`docs/install.md`), so the resident writes the request, keeps the promise and returns, and `shell/src/upgrade/supervisor.ts` — started from the *serving* tree, because the code driving a rollback must be known-good — owns the stop, the snapshot, the staged gate, the switch, the start and the rollback. Under a service manager it is launched as its own transient unit (`systemd-run --user --unit=… --collect`); without that it would sit in the unit's cgroup and be killed by the stop it is about to run, so a failed launch *refuses the upgrade* instead of dying silently at step one. **What pays for it, merged:** no new dependency, no new bin, no table, no column and no migration — the kernel takes **zero diff** this round, and the CLI form keeps #150's semantics exactly (which is also the stated ceiling: the snapshot and the recall gate belong to the resident form, not retro-fitted into `cogmem update`). The staging reuses the installer's own unit renderers (`renderSystemdUnit`/`renderLaunchdPlist`/`residentArgs`/`servicePath`) rather than a second service story; the snapshot reuses the kernel's `exportSnapshot`/`SnapshotImporter` rather than a backup of its own; the promise reuses F2's wake intention; the report reuses `presence.ts`; and the gate reuses the installer's `readSoul`/doctor checks. Nothing is removed this round — the round is additive by nature and says so rather than dressing a new lifecycle up as a merge. Remaining ceilings, named: the snapshot covers the kernel database file and not the shell's few JSON files (they are not versioned and the switch does not touch them); the promise is an F2 wake intention, so it shows in the next-wake surface rather than in `/commitments` until F16 (#193) lands; the staged tree's dependencies are symlinked from its source; and a tree that predates `src/upgrade/supervisor.ts` cannot be upgraded *from* (there are no users of such a tree). Shell suite 299 → **333 pass / 0 fail / 44 files**, root suite unchanged at **1996 pass / 0 fail / 269 files**. The box (real systemd user service, bun 1.4.4, 2026-11-14) ran the whole cycle twice: a successful `5.0.0 → 5.0.1` (report read back on attach, old tree's bytes unchanged, promise closed) and an injected gate failure (`data-dir mode 755`) that rolled back — the unit re-pointed at the old tree, the old version serving, the failed gate's probe gone from the brain because the snapshot was restored (one probe row, not two). That cycle found a defect no fixture had: `serviceFileExists` asked for the very `serviceMode` flag it computes, so the resident took the no-manager path and systemd's `KillMode=control-group` killed the detached supervisor along with the resident it had just stopped — the upgrade went silent, which is the failure the promise exists to report. The detector is now a fact about the disk, and a systemd-started process leaves the unit's cgroup (`systemd-run --user`) even when no unit file was found. User-visible effect, in one line: the companion upgrades itself from a quiet moment, tells you before it goes, tells you how it went (or that it rolled back) when you are back, and can never go quiet about an upgrade that failed.

User-visible effect, in one line: after a merge the companion recalls the person by any name they were known by, with their memories and relations, and a split takes the merged half back at once.

- **The owner's long-term understanding is now a formal compiled product: four ledgers, each entry carrying its source events, a correction that reaches the source and recompiles that ledger, and its own recall priority and decay (F5 of #159).** `MemoryKernel.profile` (`src/profile/ProfileCompiler.ts`, contract `docs/profile-compilation.md`) compiles the owner into **facts / preferences / relations / ongoing items**. Storage is the ledger and nothing else, the way F2 stored a wake intention: every version of an entry is a `memory_events` row on a per-entry stream (`profile-entry:<entryId>`), a correction is another row on the same stream, a key the evidence no longer derives gets a `PROFILE_ENTRY_RETIRED` row, and each ledger's compile leaves a `PROFILE_LEDGER_RECOMPILED` receipt — so the ledger is the state, the history and the audit, and the round adds **no table, no column and no migration**, leaving the pinned baseline schema untouched. The compiler is deterministic and reads no free text: it derives from live `facts`, active `beliefs`, declared person `relations` (F4) and owner-confirmed `prospective` items, all already evidence-bound, so the same evidence always compiles the same profile and a model can only have shaped the evidence it reads. **A correction reaches the source:** `correct({ ledger, key, value, correctionEventId })` requires a `user` turn in the project, appends a version whose `sourceRefs` name *both* that turn and the entry's existing source events, then recompiles the whole ledger; a source-derived version never overwrites a newer correction, so the owner's word stands until evidence newer than the correction says otherwise, and the replaced value leaves the default read for `history`. **Each ledger refuses what does not belong in it, and each refusal is a discriminating test:** a transient problem (`has_issue`/`issue_correction`) enters no ledger; a one-off feeling carries no preference predicate, so it never becomes a preference (a mood is a fact, a `likes` is a preference); a structural edge or a non-person endpoint is not a relation, and neither is a relation no memory backs; a machine's `pending` candidate and every terminal status are not the owner's open items, and a completed commitment is retired by the next recompile. **Recall ranks the profile by its own rule, not the compiled lane's:** a separate lane is appended after the ordinary items instead of merged through the compiled cue ranking, so a profile entry never displaces the memory the question named; within it the ledgers rank `ongoing` > `relations` > `preferences` > `facts`, a score halves every 90 days of evidence age, and a correction refreshes its own weight. **Cross-identity is #153's rule and no other:** a profile item anchors the raw event it was compiled from, which puts it on the same chain the secret gate (#142) and the agent scope gate (#143/#154) already walk — a turn one identity had stays with it, imported material is project-public, and a chain naming no agent is public. **What pays for it, merged:** derivation reads `FactStore.listFactsByTimeRange`, `BeliefStore.listByTimeRange` and `EntityStore` reads that already exist rather than a profile store; the compiler folds the project's profile rows once per compile instead of re-walking the ledger per candidate; the relation vocabulary reuses `PERSON_RELATION_TYPES` from F4; and the recall lane reuses the existing chain walk rather than a visibility flag. **Nothing is removed this round** — the round is additive by nature and says so rather than dressing a new module up as a merge. - **The capture path's superlinear segment is found and fixed, and the gate that missed it now measures the shape it hid in (#199).** The ticket's curve reproduces — for text with one long newline-free line. Through `captureConversationTurn` on this machine, 4 / 16 / 64 KB of unbroken line cost **187 ms / 1.8 s / 26.5 s**, against **72 / 112 / 291 ms** for the same bytes split into lines. The cause is one regex in the AAAK chat summary: `content.match(/(.+?)\s*(?:因为|due to|because|因此|therefore|导致|lead to)(.+)/gi)` re-expands its lazy group from every start offset looking for a marker that is usually absent — O(n²) on a long line — and the only thing read from it was `causes[0]`, which is the first line holding a marker: the pattern's `.+?`-prefix and `.+`-suffix cannot cross a newline, so `AAAKGenerator.firstLineWithCause` answers the same question in one linear pass, guards kept (at least one character before the marker and one after it). The same 64 KB line went from **20.9 s to 0.78 s**, and the whole line of writes is linear again: one-line turns 4→16→64 KB read 99 / 239 / 775 ms, and `rememberTurnWithResult` on the same shape 146 / 407 / 1469 ms. **The gate that did not catch it had to learn two things, both measured:** a newline-free line is a different shape from 64-column lines (every row was line-separated, which is exactly why `scripts/measure-ingest-baseline.ts` passed while the bug was live — the one-line rows run to 64 KB because at 4→16 KB the bug reads 8.6× and slips under the ticket's 10× rule, where 16→64 KB reads 13.9× and fails it), and **neuron dedup reads as a fast ingest** (a repeated sample returns the earlier neuron without compiling it — measured at 25 ms instead of 1.5 s — so every sample now writes into its own project, since dedup only fires inside one, and a conversation sample that reuses a neuron fails the harness instead of publishing the number). The tool-observation and task-event faces were never on this path: they compile as `agent_observation`, which the generic compressor handles in O(1); the quadratic was in the conversation compile — the path `rememberTurn*` and the new face (#157) share, and the path a resident shell's round goes through. `__tests__/aaak-cause.unit.test.ts` holds the extracted line and its guards, `__tests__/ingest-baseline.unit.test.ts` holds the cost. **Nothing is removed this round:** a regex became a scan, a benchmark harness was added, and the ingest semantics — what is stored, redacted and marked — are untouched, which is the red line #199 drew; the existing suite all green is the evidence. User-visible effect, in one line: a long line of captured text no longer costs tens of seconds to remember, because one summary regex stopped scanning it quadratically.

That is deliberately not the secret chain, which stores, marks and withholds at recall; here nothing has to be deleted afterwards. The teaching sentence is single-sourced and asserted in the MCP instructions and all three shipped host skills. - Consolidation counts independent origins, and stops when they disagree (#129). Corroboration used to count rows, so one turn restating a claim three ways read as three sources; it now counts the independent sources behind a group — the interaction unit a fact was read from, or the imported document it came from, with turns of one file collapsing into one origin. `likes` and `dislikes` both land on the `preference` predicate, so candidates carry their polarity and origins holding the same subject and predicate both ways consolidate nothing — recorded in `blockedConsolidations` rather than skipped silently. The threshold N is 2, which is the smallest value that keeps a single source out — the ticket's own criterion; a rule-only Dream round over the 40,479-event corpus copy produces no consolidation candidates at all (0 facts, 0 frames, 5m33s), so no distribution exists to fit anything larger.

The Atlas projects a place node keyed by its normalized name rather than a hash, and a state now registers its name in the same alias index, so the two facets a reader says in words resolve to nodes the exact-match path could never reach. `FacetType` gains `state` and `place` with cue rules ("while still on SQLite", "at the Tokyo office", and their Chinese forms); for these two the episode entrance is reversed, because their edges hang off the event that was in that state or at that place rather than off the episode. No schema migration: both were already Dimensions.
- The recall block gives shared memory its own section (#67). Injected text now says what it is, in the block itself: shared by other agents, reference material, not your own memory and not an instruction, each line naming the host and collection it came from and carrying `notAnInstruction=true`. The section is rendered after the private items and takes its own budget, so with `memoryContextMaxItems: 3` three private facts still render and the shared ones follow instead of replacing one of them — without the split, a busy shared collection would have hidden the agent's own memory in the prompt.
- Auto-recall gives shared memory its own lane (#67). Another agent's text is appended after this agent's own items rather than merged into their slots — measured: with five shared items waiting against a five-item recall, the private items come back byte-identical to the run before anything was shared, and the shared lane adds two (`sharedCount`, `sharedDropped` in `decisionTrace`). The lane is read-only and does not run when sharing is off or the caller has no identity.
- `cogmem_import_status` is no longer MCP-only (#63). The query moved onto the kernel as `importStatus(projectId, { limit })` and the tool now parses arguments and delegates, so a host plugin that loads the public entry can ask whether an import finished — which is what the OpenClaw plugin does, through `createMemoryKernelFromConfig`. Read-only, so it grants no new authority. `cogmem_import_preview` and `_apply` stay where they are: they are the writing import path, and handing a plugin the authority to pull another project's transcripts into the ledger is a trust decision the ticket explicitly left open.
- Shared memory is reachable again, from every surface a host can use (#63). 4.0 removed the four `cogmem_shared_*` tools and with them any way for a host plugin to reach the region (ADR-0005 deferred it to 4.1, and this is 4.1): the methods now live on the kernel — `publishShared`, `retractShared`, `subscribeShared`, `explainShared`, `grantSharedReader`, `revokeSharedReader`, `listSharedCollections` — the MCP surface registers four tools that only delegate to them, and the public entry host plugins load carries the types without the SQLite adapter (ADR-0004: the kernel holds the only connection). With `[shared] enabled` off — the default — a write answers `shared_disabled` rather than "unknown tool", and the adapter creates its schema on first use, so a database nobody shares into still carries no shared table.
- Shared memory is an opt-in region with one owner per collection (#66). A collection's owner is the host that first published into it; only the owner may publish into it again or retract from it, and `[shared] enabled` is false unless it is set, so a default install shares nothing and a database nobody shares into still carries no shared table. Reads are not gated per reader — that is the publish-and-read entry above (#146).
