## 2. Found and fixed during this audit

**#89 — `update` targeted npm's default prefix, then silently fell back when it could not
determine one.**

First half (`37a9d70`): on a `--prefix` install, `update` ran a bare `npm install -g`, which
resolves npm's *configured* default — `EACCES … /usr/lib/node_modules/cogmem` here, and
silently the wrong tree wherever that default is writable.

Second half (`fa843f3`): when the owning prefix could not be derived at all, it still printed
and ran the bare command. Now a real run **refuses** with a non-zero exit naming
`COGMEM_NPM_PREFIX`; a dry run reports `prefixUnknown: true` and **omits `nextCommand`**,
because a dry run that prints a command it would refuse to run is worse than one that prints
nothing. `nextCommand` is also shell-quoted where needed, so a prefix containing a space
survives being copied — asserted by running the printed command through a shell with npm
stubbed and checking the prefix arrives as one argument.

Verified on a real custom-prefix install of this candidate: the reported command names the
prefix that owns the running copy, `update --yes` replaces it (`changed 209 packages`), and
the gate is unchanged before and after.
