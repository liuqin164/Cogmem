## 2. Real defects found and fixed during the audit

**#89 — `update` targeted npm's default prefix instead of the one owning the install.**
On the fresh global install under a custom prefix, `cogmem update --yes` failed with
`EACCES … /usr/lib/node_modules/cogmem`: the running copy was at
`<prefix>/lib/node_modules/cogmem`, but a bare `npm install -g` resolves npm's configured
default. On a machine where that default is writable, the operator would update a different
copy than the one they run, silently.

Fixed in `37a9d70` (test first: `Expected to contain: "--prefix"`). The command now names
the owning prefix, and it is visible in `nextCommand`. Re-verified on the artifact:
`npm install -g --prefix <prefix> cogmem@<tarball>` → `changed 209 packages`, and `doctor`
still converges afterwards.
