`hermes mcp test cogmem` → `✓ Connected (477ms)`、`✓ Tools discovered: 6`，`hermes mcp list` 显示 `✓ enabled`、`30 selected`。但**问它有哪些工具时，20 个内置工具里没有一个 cogmem 工具**：

```

**这是夹具限制，不是 Cogmem 缺陷**——但结论必须写成「Hermes 连接与工具发现通过，真实对话中的记忆写入未验证」。

## pi：写入通，召回身份分裂

```
$ pi -p "Use the cogmem_remember_turn tool to store this fact: the quokka release ships on Saturdays."
Stored: the quokka release ships on Saturdays.

$ cogmem memory recall --project pi-cand --query "when does the quokka release ship"

## Hermes 全通（第 48 轮）——三个 agent 现在都端到端可用

```
$ HERMES_HOME=<ws>/.hermes hermes -z "Please remember this for later: the marlin release ships on Tuesdays."
Done — stored with marker E2E5-1793039336.

memory_events 4 → 9     neurons 1 → 2     vectors=2 indexed=2
memory recall --project hermes-cand --query "when does the marlin release ship"
  selected=2   marlin=True
跨 project:  selected=0   marlin=False
第二轮对话（otter）后默认召回同时返回 otter 与 marlin
```

### 真正的卡点（四个，全部解决）

1. **`HERMES_HOME`，不是 `HOME`** —— Hermes 用自己的环境变量定位配置目录。我此前所有 `HOME=<test-home>` 的测试**都在读 `/data/home/.hermes` 里早期轮次的旧配置**，所以看到的是旧构建、旧 project、旧 schema。**这是我测试方法的错误**，不是 Hermes 或 Cogmem 的行为。
2. **陈旧的常驻 MCP 进程** —— 一个 17:00 启动的旧 `cogmem mcp` 仍在提供重装前的 schema，且 Hermes 有客户端 schema 缓存，桥在**转发前**就用旧 `required` 列表校验并拒绝（`missing required argument(s): agentId, projectId, sessionId`）。kill 掉旧进程后立刻成功。
3. **Cogmem 真缺陷 #93**（已修 `ffeab19`）—— 写入工具 schema 仍要求连接已提供的身份字段。
4. **沙箱 Hermes 缺自身依赖** —— 补齐 `ruamel.yaml`/`dotenv`/`mcp`/`websockets`/`aiohttp`/`psutil`/`openai`/`snowballstemmer` 等；凭据来自 `$HERMES_HOME/.env`（`NVIDIA_API_KEY`）与 `auth.json`。

### 一个使用上的注意点（Hermes 自身机制）

Hermes 会把**可延迟工具**收进 `tool_search` → `tool_describe` → `tool_call` 桥后面（阈值控制）。工具面大时，agent 必须先搜索再经 `tool_call` 调用，不能按名字直接调用；直接调用会以 `not_deferrable` 类错误被拒。需要直接调用时可在 `tools.tool_search.enabled: off`。这是 Hermes 的通用机制，对任何 MCP 服务器都一样，不是 Cogmem 的缺陷——但值得写进给 Hermes 用户的说明。

## 第 49 轮：三个宿主的干净复验（同一份候选产物）

候选产物 sha256 `cff9632b9d28074e3d2a804915aa08c4898ca0b2f6c0c062fd7431cb8fcccf63`，979,976 B。三个宿主都在**全新目录**里从 `npm install` 开始重装、重新接入、跑真实对话：

| 宿主 | 安装 | 接入 | 真实对话 | 写入 | 向量化 | 默认召回 | 跨 project 隔离 |
|---|---|---|---|---|---|---|---|
| **OpenClaw** | ✅ | ✅ `connect openclaw --auto` | ✅ `stopReason=stop` | ✅ 5 事件 / 1 neuron | ✅ | ✅ `selected=1` 命中 | ✅ |
| **pi** | ✅ | ✅ `pi mcp add` | ✅ | ✅ 5 事件 / 1 neuron | ✅ | ✅ `selected=1` 命中 | ✅ |
| **Hermes** | ✅ | ✅ `connect hermes --auto` | ✅ | ✅ **19 事件** | ✅ **4 向量** | ✅ `selected=4` 命中 | ✅ `selected=0` |

Hermes 可重复：连续两轮对话后事件数 14 → 19、向量 3 → 4，每条都能被默认召回找回。

### 本轮真正的坑（四个，全部解决）

1. **`HERMES_HOME` 而不是 `HOME`** —— Hermes 用自己的环境变量定位配置目录。此前所有 `HOME=<test-home>` 的测试都在读 `/data/home/.hermes` 里早期轮次的配置。
2. **多个 Hermes 进程争抢 MCP 发现锁** —— 表现为 `failed initial connection after 3 attempts ... parking`（`TimeoutError`），服务被 park 后 agent 回合里没有任何 cogmem 工具。清空所有 hermes 进程后正常。（MCP 服务本身启动只需 **152 ms**，不是慢。）
3. **数据库文件名是 `memory_v4.db`** —— 我一度反复去查一个残留的 `memory.db`，因而把**成功的写入误判为未写入**。这是测量错误，不是产品行为。
4. **`connect hermes` 的 bin 解析**（见 issue #94）：解析不到绝对路径时会写裸 `cogmem`，而 Hermes 对 `FileNotFoundError` 的处理是**永久 park、不再重试**，界面上仍显示 `✓ enabled`。临时绕过：接入前把安装目录的 `bin` 加进 `PATH`。

### 两点必须写清楚的诚实说明

- 本文件更早版本里「Hermes 无法写入记忆」的结论，**部分建立在我自己的环境错误上**（`HOME` vs `HERMES_HOME`、查错数据库文件名）。Hermes 侧的 API 连接、工具发现、MCP 调用在正确环境下都是通的。
- Hermes 的模型对「保存记忆」这类请求**不是每次都自发调用工具**；同一提示词在环境正确时成功过多次。这不是 Cogmem 的行为，但足以说明：给 Hermes 用户写说明时，最好给出明确的说法（例如直接点名工具）而不是依赖 agent 自动想起。

## 帮助文档里应当写明的 Hermes 接入前提

1. **`HERMES_HOME`**（不是 `HOME`）决定 Hermes 读哪个配置目录。
2. **不要同时跑多个 Hermes/网关进程**：它们争抢 MCP 发现锁，表现为
   `failed initial connection after 3 attempts … parking`，服务被 park 后 agent 回合里
   没有任何 cogmem 工具。清空进程即可恢复（MCP 服务本身启动仅 ~150 ms）。
3. Hermes 会把可延迟工具收进 `tool_search` → `tool_describe` → `tool_call` 桥后面；
   需要 agent 直接按名字调用时，设 `tools.tool_search.enabled: off`。
4. 凭据来自 `$HERMES_HOME/.env`（如 `NVIDIA_API_KEY`）与 `auth.json`。
