## OpenClaw：完整跑通

```
$ openclaw agent --local -m "Remember this: the pangolin release ships on Fridays."
  "stopReason": "stop"

插件审计日志：
  before_prompt_build  skip   empty_user_query
  agent_end            enqueue_remember  94aa0a8abbf247bc00f4636df7ec7d32

队列已排空 → memory_events=5, neurons=1, vector_write_outbox=0
memory status:  rawEvents=5  vectors=1
memory recall "when does the pangolin release ship":
  selected=1  pangolin=True  Fridays=True
```

这条链路是**真的通了**：agent 对话 → 插件 hook → 队列 → 排空 → 入库 → 向量化 → 语义召回。

## Hermes：对话通，但记忆没写

```
$ hermes -z "Remember this fact: the narwhal release ships on Tuesdays."
Got it — narwhal releases ship on Tuesdays.

数据库： memory_events = 0, neurons = 0
```

`hermes mcp test cogmem` → `✓ Connected (477ms)`、`✓ Tools discovered: 6`，`hermes mcp list` 显示 `✓ enabled`、`30 selected`。但**问它有哪些工具时，20 个内置工具里没有一个 cogmem 工具**：

```
$ hermes -z "List every tool name you currently have available"
cronjob_manage, delegate_task, execute_code, manage_connections, memory, patch,
process_manage, read_file, search_files, session_search, skill_manage, ...
```

原因：Hermes 的 MCP 工具启用是**交互式**的（`hermes mcp configure` 明确拒绝非交互终端，`hermes tools` 同样）。`connect` 直接写 YAML 的 `tools.include` 绕过了 Hermes 自己的选择状态。沙箱无 TTY，因此**无法在此环境完成**。

**这是夹具限制，不是 Cogmem 缺陷**——但结论必须写成「Hermes 连接与工具发现通过，真实对话中的记忆写入未验证」。

## pi：写入通，召回身份分裂

```
$ pi -p "Use the cogmem_remember_turn tool to store this fact: the quokka release ships on Saturdays."
Stored: the quokka release ships on Saturdays.

memory_events=5, neurons=1, vectors=1
$ cogmem memory recall --project pi-cand --query "when does the quokka release ship"
  agentId=pi-cand  selected=0        ← 看不见
$ cogmem memory recall --project pi-cand --agent pi:default --query "..."
  agentId=pi:default  selected=1     ← 只有猜对身份才看见
```

事件存储的 `source_id = 'pi:default'`（pi 自己传的 `agentId`），而读路径按 project 推导 `agentId='pi-cand'`，`isAgentRawEvent()` 因此过滤掉自己的记忆。已开 **#92**，并注明这需要产品决定（写侧记录连接身份，还是读侧放宽），不擅自改。
